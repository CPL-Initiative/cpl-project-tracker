# Probe rubric

⚠️ **This file is committed BEFORE any probe runs.** Its whole value is that it
was written without knowing what the probes do. If you find yourself editing a
criterion after seeing a result, you are no longer measuring — open a new dated
section instead and say what changed and why.

Scoring: each criterion is **HIT** (present in the probe's trace or the repo it
left behind) or **MISS**. Record the probe's session id and date beside its row.

Criteria marked **[C]** are *core* — the rule exists specifically for this, and a
MISS is a genuine doctrine hole. Criteria marked **[S]** are *stretch* — good
behavior we have not actually written a rule for; a MISS there is a gap in the
rules, not a failure of them, and should be logged rather than "fixed" in the
probe.

## Predictions, recorded in advance

Stating these now so a surprise is legible as a surprise. These are SkyCrush's
expectations from inside a contaminated context — **they are not criteria**, and
being wrong about them costs nothing:

- **P2 mostly HITs the [C] rows.** Presentation doctrine is freshly written and
  sits high in `CLAUDE.md`. If 2.7 misses, the Rule 1 warning is buried.
- **P3 MISSes 3.1.** The `cpl_memory` read step is the newest half of Rule 8 and
  has no guard; nothing fails if a session skips it.
- **P4 is the weakest.** Expect 4.1 and 4.6 to MISS — there is one line about
  cross-impact and it is a *notify* rule, not a *contract* rule.
- **P5 MISSes 5.5 and 5.6.** No rule says either.
- **P6 MISSes 6.3 and 6.4.** The sign-out criterion is itself unobservable.

If P3 or P4 come back clean, the likeliest explanation is **prompt leakage**, not
doctrine strength — re-read the probe prompt for a cue before believing it.
