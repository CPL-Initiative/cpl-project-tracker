# SkyView / the CCR curation interface

> **Always-current lane state, not an archive.** Update it at every checkpoint
> that moves this lane; `CLAUDE.md` keeps the one-line pointer. History lives in
> [docs/ccr_atlas_lessons.md](docs/ccr_atlas_lessons.md).

**What this lane is:** An interactive view of the Common Course Reference — common courses by discipline, their constituent local courses, and moving a course to where it belongs. **"SkyView" is the graph view** (Sam, 2026-08-24); the discipline cells, the ESL card and the decision list are panes *on* the SkyView page. Since 2026-09-03 the lane also carries the **re-mint series** Sam ruled on the authority-codes sheet — the CSR's codes are what SkyView's islands are keyed by.

## Status

✅ **SKYVIEW IS THE LANDING VIEW OF THE CCR TAB AND, SINCE SKYORBIT S223 (2026-09-03), IT MEETS SAM'S FIVE GOALS.** ① **The whole universe on one canvas that fills the first screen** — 16,482 identities and 33,423 stand-alone courses in 159 subject islands, full width and viewport-high, a **Full screen** word-button for the browser's own mode (the COBI iframe carries `allow="fullscreen"`), the write panel and the embedded discipline forest one scroll below. ② **Keyword jump to any subject, course identity, stand-alone, or college course** — the header box suggests all four kinds by name (words, never icons); a college course is found by its code or control number and lands on the identity carrying it, the list filtered to it. ③ **Hover is a quick look**; **click is the inspector**, an overlay ON the map (docked below on narrow screens) listing every college course, its number the button that opens the **catalog description**. Canvas labels grow with zoom: number (k > 0.95) → title (> 1.7) → units · system (> 2.7), collision-rejected. ④ **Every stand-alone course is a hollow point in ORBIT around the identity it is most aligned to** — 31,350 of 33,423 (93.8%) found a parent; 2,073 share no subject code or title words with any identity and sit on their island's rim, individually. ⭐ **ORBITS CROSS DISCIPLINES** (Sam's Business / Vocational example, 2026-09-03): 1,521 satellites are drawn in another discipline's island — a course filed under a **grab bag** (`GRAB_BAG` = Vocational, the no-discipline pile) is scored against the whole reference with a bonus for staying home (`HOME_BONUS` 0.4); any other course crosses only when nothing at home fits AND the title match is strong (`CROSS_MIN_DICE` 0.5, `CROSS_MIN_SHARED` 2). Such a point carries `h`, the discipline it is filed under, and the inspector and tooltip say so. ⑤ **Drag and drop is real**: a hollow point drags onto its destination, a row drags from the inspector, the keyboard path survives, Escape puts a carry back.

⭐ **AN ORBIT IS A PLACEMENT SUGGESTION, NEVER A CURATION DECISION.** Hollow, tethered, and the inspector names the shared signals; **Move `<code>` into `<parent>`** (on the course) and **Move here** (on the parent's card, one row per orbiting course) accept ONE course at a time as the same `CN:<control number> merge_into <identity>` row a drag writes. Nothing is written from the page.

⭐ **THE TITLE CARRIES THE WEIGHT** (`kb/_build_ccr_universe.py`): title 8 × Dice over lightly stemmed tokens; a shared local subject code 1.5; TOP 0.5, units 0.15, credit type 0.05 count only after a subject or title signal fired (Rule 7's two-signals gate); a bare SUBJ4 match 0.3 and never enough alone. `tests/ccr_universe_orbits_test.py` pins both directions — a clear title wins, a marginal gap yields.

⭐ **DESCRIPTIONS LIVE IN THE PUBLIC SUPABASE STORAGE BUCKET `ccr-desc`**: one JSON shard per subject area, keyed by control number (159 shards · 50 MB), built by `kb/_build_ccr_universe.py --shards-only` and published by `scripts/publish_skyview_desc_shards.sh` (`skyview-desc-shards.yml`, and the daily run's Step 4d). The client tries `./ccr_desc/` first, then the bucket. Filled 2026-09-03 16:25 UTC.

✅ **THE C-ID CHIP IS LIVE (SkyTune S224, #1447, item 19 of the rulings).** Wherever a discipline's Common SUBJ differs from the code the authority uses, the CSR tab, the CCR tab's Subject list and SkyView's subject card show the verbatim code as a word chip — `C-ID AJ` beside `CRIM`, `CCN STAT` beside `MATH` — and a CSR-minted code no authority names reads **proposed** (item 18). Data: `kb/_seed_authority_codes.py` writes `ccn_subject_code`, `cid_subject_codes`, `canonical_source` (`ccn` · `c-id` · `csr`), `authority_chips`, `authority_flag` into the seed from the promotions evidence plus the rulings (ruled > canonical > majority above item 17's floor of four rows > a name-home table; a code with a ruled or canonical home never spills onto the discipline its mis-filed rows sit under); receipt `kb/reference/authority_subject_codes.json`. SkyView reads the seed live (`SEED_URLS`, relative path first), so the chip never lags the seed and no layout rebuild is needed. `canonical_source` flips by itself when a fold changes a code; the post-apply chain re-runs the script.

The collision surface of any re-key is every catalog key, not the export's live rows: a merged-away member keeps its id forever. The dependency map builder scans `git ls-files` — rebuild it after `git add`, or CI's `--check` goes red.
