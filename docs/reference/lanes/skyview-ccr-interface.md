# SkyView / the CCR curation interface

> **Always-current lane state, not an archive.** Update it at every checkpoint
> that moves this lane; `CLAUDE.md` keeps the one-line pointer. History lives in
> [docs/ccr_atlas_lessons.md](docs/ccr_atlas_lessons.md).

**What this lane is:** An interactive view of the Common Course Reference — common courses by discipline, their constituent local courses, and moving a course to where it belongs. **"SkyView" is the graph view** (Sam, 2026-08-24); the discipline cells, the ESL card and the decision list are panes *on* the SkyView page.

## Status

✅ **SKYVIEW IS THE LANDING VIEW OF THE CCR TAB AND, SINCE SKYORBIT S223 (2026-09-03), IT MEETS SAM'S FIVE GOALS.** ① **The whole universe on one canvas that fills the first screen** — 16,482 identities and 33,423 stand-alone courses in 159 subject islands, full width and viewport-high, a **Full screen** word-button for the browser's own mode (the COBI iframe carries `allow="fullscreen"`), the write panel and the embedded discipline forest one scroll below. ② **Keyword jump to any subject, course identity, stand-alone, or college course** — the header box suggests all four kinds by name (words, never icons); a college course is found by its code or control number and lands on the identity carrying it, the list filtered to it. ③ **Hover is a quick look** (number · title · units · identity system · courses carried · what it orbits); **click is the inspector**, an overlay ON the map (docked below it on narrow screens) listing every college course as a row whose number is the button that opens the **catalog description**; titles and units arrive with the same shard. Canvas labels grow with zoom: number (k > 0.95) → number · title (> 1.7) → number · title / units · system (> 2.7), collision-rejected, never stacked. ④ **Every stand-alone course is a hollow point in ORBIT around the identity it is most aligned to** — 31,350 of 33,423 (93.8%) found a parent; 2,073 share no subject code or title words with any identity and sit on their island's rim, individually. The "· stand-alone" twin islands (Kinesiology's held 2,400 points in one disc) are gone. ⭐ **ORBITS CROSS DISCIPLINES** (Sam's Business / Vocational example, 2026-09-03: *"vocational is a big grab bag of noncredit courses and many need to stay there and some need to be moved to a MID course in another discipline"*) — 1,521 satellites are drawn in another discipline's island: a course filed under a **grab bag** (`GRAB_BAG` = Vocational, the no-discipline pile) is scored against the whole reference with a bonus for staying home (`HOME_BONUS` 0.4); any other course crosses only when nothing at home fits AND the title match is strong (`CROSS_MIN_DICE` 0.5, at least two shared title words — `CROSS_MIN_SHARED` — so one common word cannot carry a course across). Such a point carries `h`, the discipline it is filed under, and the inspector and tooltip say so ("filed under Vocational; the closest match in the whole reference is here, in Business"). ⑤ **Drag and drop is real**: a hollow point drags onto its destination, a row drags from the inspector onto the map, **Drag…** + click and the keyboard path survive, Escape puts a carry back.

⭐ **AN ORBIT IS A PLACEMENT SUGGESTION, NEVER A CURATION DECISION.** Hollow, tethered, and the inspector names the shared signals; **Move `<code>` into `<parent>`** (on the course) and **Move here** (on the parent's card, one row per orbiting course) accept ONE course at a time as the same `CN:<control number> merge_into <identity>` row a drag writes. Nothing is written from the page.

⭐ **THE TITLE CARRIES THE WEIGHT** (`kb/_build_ccr_universe.py`): title 8 × Dice over lightly stemmed tokens; a shared local subject code 1.5; TOP 0.5, units 0.15, credit type 0.05 count only after a subject or title signal fired (Rule 7's two-signals gate); a bare SUBJ4 match 0.3 and never enough alone. Floor: Dice ≥ 0.25, or a shared local subject with any title overlap. The first build let the corroborator stack outvote a clear title ("Swim Training for Competition" landed on "Aerobic Weight Training" over a swimming identity); `tests/ccr_universe_orbits_test.py` pins both directions — a clear title wins, a marginal gap yields.

⭐ **DESCRIPTIONS LIVE IN THE PUBLIC SUPABASE STORAGE BUCKET `ccr-desc`** (Sam's lean of 2026-08-24, delivered): one JSON shard per subject area, `{ "<cn digits>": [description, title, units] }`, 159 shards · 50 MB, **keyed by control number** so a dropped keyless member cannot shift the rest and a layout rebuild cannot invalidate them. Built by `python3 kb/_build_ccr_universe.py --shards-only`, published by `scripts/publish_skyview_desc_shards.sh` from `skyview-desc-shards.yml` (manual) and the daily workflow's Step 4d (when the unified-courses artifacts changed). The client tries `./ccr_desc/` first (a local `http.server`), then the bucket; under `file://` it says so. Schema of record `kb/supabase_ccr_desc_bucket.sql`; governance `bucket:ccr-desc` and the workflow are mapped to CA-01. The first dispatch after the merge (2026-09-03 16:25 UTC) filled it: 160 objects, 52.7 MB, `_manifest.json` plus 159 shards.

**Durable facts that carry over:** grinding the whole merge queue perfectly lands at 35,937 — 14.4× short of 2,500 — so **packaging** is the only mechanism with the right shape (ESL proved it at 85:1; target ≈17 per discipline); the corpus is ~5,700 decisions, 97.1% ≤ 12 identities; 3,001 carry NO discipline — a different job; the work surface behind the map (decision packs) is 1.2% built — 5 of 159 subjects; `CN:<control number>` names more than one course on 1,761 keys in this payload (3,634 draggable rows) and those moves are refused with the reason; a subject-name match outranks a course-title match in search; the page must be SERVED, not opened; `unified_courses_data.js` carries two identity ids twice (`ENGL 100`, `ITIS 160`) — the builder keeps the first and names them. The layout is rebuilt by hand (`python3 kb/_build_ccr_universe.py`, ~20 s) and committed; the daily run does not rebuild it.
