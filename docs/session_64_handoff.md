## Patterns that worked

- **Iframe a self-contained bundle as a tab** — almost zero glue (auto-derived
  `VALID_TABS`); reuse its own auth. Two load-bearing one-liners: `target="_top"`
  on links out, and a **directory** iframe `src` so the magic-link redirect
  matches the registered Redirect URL.
- **Tokenless GitHub write** via a `…/new/{branch}?filename=&value=` deep-link;
  cap the prefill (~6 KB) and fall back to Copy/Download for long docs.
- **Dodge the proxy's 256 KB cap** by extracting attachment *text* in-browser
  (pdf.js/mammoth/SheetJS) instead of sending base64 document blocks; downscale
  images to fit; a size guard drops images → trims text, never silently exceeds.
- **Reuse the existing `cpl-proxy` + `claude-sonnet-4-5-20250929`** (CORS already
  allows `cpl-initiative.github.io`) — no new secret, consistent model.
- **Commit-the-test:** pure logic in `composer_util.js` (classic script →
  `window.KBComposer`) is node-unit-tested; browser-only bits degrade gracefully.
- **Ship on green, Sam smoke-tests live, iterate.** Five PRs in one session.

## Safety patterns to honor

- **Rule 4:** `CPL_Dashboard.html` ≡ `index.html`, byte-identical. The KB tab
  markup lives in BOTH (static template; not regenerated by
  `excel_to_dashboard.py`, so it survives the daily cron).
- **Privacy firewall:** the portal + composer are for **public** KB content only.
  `map@rccd.edu` is deliberately OFF the portal allowlist; never route
  private/CPLBrain material through it.
- **Stale-shell caching:** after a deploy the portal's `index.html`/`app.js` are
  browser-cached (reader content looks current because it's fetched live). Tell
  Sam to hard-refresh; it's not a bug.
- **No GitHub write token in the app** — the Tier-1 posture is the whole point;
  don't "improve" it into a token-bearing client without re-architecting (Tier 2).
- **Auto-merge:** merge your own PRs on green (`clean` OR `unstable`); don't park
  in draft. Don't force-push `main`.
