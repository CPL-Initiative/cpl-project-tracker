## The Honors rule

- marks honors: the word Honors (or Honor) in the title, as a whole word. A code ending in H corroborates and finds the base, and never marks a course alone.
- honors program courses: a title naming only the honors program (Colloquium, Forum, Seminar, Society) has no base: it keeps its own identity and declares nothing.
- base course: the same college's course whose code is the honors code with its H removed and whose title agrees once Honors is struck (stem overlap 0.5); else the one course at that college whose title equals the honors title with Honors struck. Never itself Honors.
- new identity: the Honors members of one identity whose bases sit in that identity leave it together for one new Honors M-ID under the same discipline's canonical code; corroborated shape at two or more colleges, stand-alone at one.
- equivalence: stored as a kb_curation row (honors_id, field 'honors_of', value base identity), the field kb/_apply_curation.py must first learn (FIELDS), mirrored to kb/coci_curation.json; an id-keyed value that the alias chain and supabase-rekey.yml re-key at every later apply.
- units: units never split an identity: the Honors M-ID shows the range of what it joins; a unit difference between an Honors course and its base is shown and decides nothing.
- district guard: the rule is structural (title and code), so it needs no outcome vote; where outcome text is offered as evidence of equivalence, a pair inside one district is one voice (RCCD's BIO 1 and BIO 1H share one outline).
- top: TOP is read by nothing.
