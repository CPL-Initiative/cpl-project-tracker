# Is a CourseControlNumber a unique course key?

Audit of `kb/reference/coci_course_list.xlsx` — 2026-08-25. Generated by `kb/_audit_control_number_claims.py`. READ-ONLY.

- raw rows: **141,738**
- rows with no usable control number (blank or a `NULL` sentinel): **44** — these cannot be dragged at all
- distinct control numbers: **139,834**
- control numbers resolving to more than one row **as the artifact builds them**: **1,814** (1.30%)
- of those, naming more than one course **in the source, once the declared institution fold is applied**: **462**

Both numbers are true and they answer different questions. The first is what a consumer sees and what the `CN:` write key has to cope with; the second is what the data actually says.

## The classes want different repairs

| Count | Class | What it is |
|---:|---|---|
| 73 | TWO REAL COURSES share one control number | The key cannot express which. A re-home is unsafe here and an audit worklist item upstream in COCI. |
| 112 | Two INSTITUTIONS share one control number | A control number is supposed to be unique statewide. Upstream COCI/college data error; not repairable here. |
| 132 | One course carrying both its local and its CCN code | The C-ID/CCN cutover, working as intended. Not a defect — but it still makes the key non-unique, so a drag still cannot tell the rows apart. |
| 137 | One course whose code is written two ways | A formatting/representation artifact (KFIT 6.2 / KFIT 62). Cosmetic, except that it too makes the key non-unique. |
| 8 | One course whose title is written two ways | Same course, reworded. Cosmetic. |
| 1,352 | ONE course, under an institution entered twice | Not ambiguous in the source at all once the declared fold is applied — but the member roster never applies it, so the artifact still carries two rows under two college names and the key still cannot tell them apart. |

**1,371** of these read as *two institutions* until the declared fold in `kb/reference/map_college_roster_rules.json` is applied — one institution entered under two roster names (`… Continuing Education` / `… Continuing Education Credit`). That file is consulted where college names enter the EACR adoption payload; the member-college roster (`mcolleges`, built by `_mc()`) does not consult it, so both spellings reach the member tables.
